# Bitácora del proyecto

Problemas de instalación, versiones y despliegue encontrados durante el desarrollo de EntradasYa v1, y cómo se resolvieron.

## Desarrollo local (Windows 10)

| Fecha | Integrante | Problema | Solución |
|---|---|---|---|
| 17/11/2026 | Carlo Gabriel Romero | Después de instalar PostgreSQL 17, el comando `psql --version` da error en PowerShell: *"El término 'psql' no se reconoce como nombre de un cmdlet..."* | El instalador no agrega PostgreSQL al PATH. Se agregó `C:\Program Files\PostgreSQL\17\bin` a la variable PATH del usuario y se reabrió VS Code. |
| 17/11/2026 | Carlo Gabriel Romero | Al entrar con `psql -U postgres` aparece: *"WARNING: Console code page (850) differs from Windows code page (1252)"*. | Es solo un aviso de la consola de Windows: algunas tildes pueden verse mal en psql. No afecta a las bases de datos, así que se ignoró. |
| 17/11/2026 | Carlo Gabriel Romero | events (Python) rechazaba el token emitido por auth (Node.js) con *"Token inválido o vencido"*, aunque el secreto JWT era el mismo. | La librería PyJWT 2.10 exige que el campo `sub` del token sea texto y auth lo enviaba como número. Se cambió auth para emitir `sub` como texto (`"1"` en lugar de `1`), que es lo que indica el estándar JWT. Se actualizó el acuerdo del token. |
| 17/11/2026 | Carlo Gabriel Romero | Después de cambiar el código de auth, el servicio seguía respondiendo con el comportamiento anterior. | El servidor iniciado con `npm start` carga el código una sola vez. Hay que detenerlo (Ctrl + C) y volver a iniciarlo. Para desarrollar se usa `npm run dev`, que se reinicia solo con cada cambio. |
| 17/11/2026 | Carlo Gabriel Romero | `go version` da error: el comando no se reconoce. | Go no estaba instalado. Se instaló Go 1.27 (`winget install --id GoLang.Go -e`) y se reabrió VS Code. |
| 17/11/2026 | Carlo Gabriel Romero | Al preparar payments, `go mod tidy` subió la versión mínima del proyecto a Go 1.25. | La librería pgx v5 (conexión a PostgreSQL) exige Go 1.25 o superior. Se dejó así y se indicó en los README de payments y checkin. En Ubuntu habrá que instalar Go desde go.dev, porque el paquete de `apt` puede ser más antiguo. |
| 17/11/2026 | Carlo Gabriel Romero | Mailpit no estaba instalado y el comando `mailpit` no se reconocía después de instalarlo. | Se instaló con `winget install --id axllent.mailpit -e`. winget modifica el PATH, así que hay que reabrir VS Code para que lo reconozca. |
| 17/11/2026 | Carlo Gabriel Romero | orders necesitaba el correo del cliente para enviar la confirmación, pero el token solo traía id y rol, y el documento no permite que orders llame a auth. | Se agregaron `correo` y `nombre` al token que emite auth. orders los lee del token sin llamar a otro servicio. |
| 17/11/2026 | Carlo Gabriel Romero | `dotnet --version` dice *"No .NET SDKs were found"*, aunque .NET aparecía instalado. | En la PC solo estaba el *runtime* (sirve para ejecutar) y no el *SDK* (sirve para compilar). Se instaló el SDK con `winget install --id Microsoft.DotNet.SDK.8 -e` (versión 8.0.428). |
| 17/11/2026 | Carlo Gabriel Romero | En el correo de confirmación, el botón "Ver y descargar mis entradas" no abría nada. | El enlace usa la variable `WEB_URL` de notifications, que apuntaba a `http://localhost` (donde estará Nginx). En desarrollo la web corre en `http://localhost:5173`, así que se cambió `WEB_URL` en el `.env` local. En el servidor se usará la dirección real. |

## Despliegue en Ubuntu (AWS EC2)

| Fecha | Integrante | Problema | Solución |
|---|---|---|---|
| 17/11/2026 | Carlo Gabriel Romero | Se planeaba usar una máquina virtual en Azure, pero no se pudo activar la cuenta. | Se usó una instancia **EC2 de AWS** con **Ubuntu Server 24.04 LTS**. Igual se instala todo a mano en un solo servidor Ubuntu, como pide el documento (no se usan servicios administrados de AWS). |
| 17/11/2026 | Carlo Gabriel Romero | El tipo de instancia **t3.medium** (4 GB) no se podía elegir: *"no cumple los requisitos del plan gratuito"*. | Se eligió **t3.small** (2 GB, capa gratuita) y se agregaron **2 GB de swap** (`/swapfile`) para que alcance la memoria al compilar .NET y Go. |
| 17/11/2026 | Carlo Gabriel Romero | La consola web de AWS (EC2 Instance Connect) daba *"Error al establecer la conexión SSH"*. | Usaba el usuario `ec2-user` (de Amazon Linux). En Ubuntu el usuario es **`ubuntu`**. Además había que esperar a que la instancia pasara las comprobaciones de estado. |
| 17/11/2026 | Carlo Gabriel Romero | En la consola web de AWS no se podía pegar texto, ni con Ctrl+Shift+V ni dando permiso al portapapeles. | Se dejó de usar la consola web y se entra desde la terminal de VS Code con `ssh -i entradasya.pem ubuntu@IP`, donde pegar funciona normal. |
| 17/11/2026 | Carlo Gabriel Romero | `ssh` mostraba *"Identity file ... not accessible: No such file or directory"*. | La llave `entradasya.pem` se había guardado en el Escritorio y no en Descargas. Se corrigió la ruta en el comando. |
| 17/11/2026 | Carlo Gabriel Romero | El repositorio es privado y el servidor no podía hacer `git clone`. | Se creó una llave SSH en el servidor y se agregó en GitHub como **Deploy key de solo lectura** (Settings → Deploy keys). |
| 17/11/2026 | Carlo Gabriel Romero | La conexión SSH se cortaba sola (*"client_loop: send disconnect: Connection reset"*), una vez mientras se compilaban los servicios, y el despliegue quedaba a medias. | Se entra con `ssh -o ServerAliveInterval=30` para mantener viva la conexión y el despliegue se ejecuta en segundo plano con `nohup bash deploy/desplegar.sh > ~/despliegue.log 2>&1 &`, así sigue aunque se corte la conexión. El avance se mira con `tail -f ~/despliegue.log`. |
| 17/11/2026 | Carlo Gabriel Romero | La instalación de .NET 8 parecía congelada en *"Progress: 25%"*. | No estaba trabada: el servidor es pequeño y .NET es pesado. Terminó a los pocos minutos. Se comprobó con `dotnet --version`. |
| 17/11/2026 | Carlo Gabriel Romero | Al abrir la IP del servidor salía *"Welcome to nginx!"* en vez de la página. | Era la página por defecto de Nginx: todavía no se había ejecutado `deploy/instalar-servicios.sh`, que copia la configuración de EntradasYa y desactiva el sitio `default`. |
| 17/11/2026 | Carlo Gabriel Romero | En el servidor, un cliente no podía elegir sector al comprar. | El código funcionaba (se probó con un navegador limpio). La causa era el traductor automático del navegador, que modifica el texto de la página y rompe los botones de React. Se agregó `translate="no"` a la página y también se permite elegir el sector desde la lista de la izquierda. |
| 17/11/2026 | Carlo Gabriel Romero | El portero recibía *"No tienes permiso para esta acción"* al validar una entrada correcta. | Había dos pestañas abiertas en el mismo navegador: al iniciar sesión como cliente en una, se reemplazó la sesión del portero en la otra, pero la pantalla seguía mostrando "Pedro Portero". Se cambió la web para que todas las pestañas se actualicen cuando cambia la sesión. Para probar varios roles a la vez se usa una ventana de incógnito. |
| 17/11/2026 | Carlo Gabriel Romero | La imagen de un evento no cargaba. | Se había pegado el enlace de una página de noticias, no el de la imagen. Hay que usar "Copiar dirección de imagen" (enlace que termina en .jpg, .png o .webp). Si una imagen no carga, la web ahora muestra el fondo con el ícono del tipo de evento. |
| 17/11/2026 | Carlo Gabriel Romero | Al detener la instancia y volver a encenderla, la página dejó de abrir en la IP de antes. | AWS asigna una IP pública nueva en cada encendido. Se vuelve a correr `bash deploy/configurar-bd-y-env.sh NUEVA_IP` (actualiza el enlace de los correos sin borrar datos). Para la presentación se puede usar una IP elástica (fija). |
